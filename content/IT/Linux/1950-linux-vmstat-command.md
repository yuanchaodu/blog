# Linux vmstat 命令

`vmstat`（Virtual Memory Statistics）是 Linux 中非常常用的系统性能监控命令，用于查看**CPU、内存、进程、磁盘 I/O、交换分区（Swap）以及系统上下文切换**等运行状态。它的特点是**开销小、实时性好**，非常适合快速判断系统瓶颈。

---

# 一、基本语法

```bash
vmstat [选项] [刷新间隔] [次数]
```

例如：

```bash
vmstat
```

显示一次当前系统状态。

```bash
vmstat 2
```

每2秒刷新一次，持续输出。

```bash
vmstat 2 5
```

每2秒采样一次，共输出5次。

---

# 二、输出示例

例如：

```bash
$ vmstat 2 3
```

输出类似：

```text
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  0      0 189032  35020 842420    0    0     5     8  120  230  3  1 95  1  0
 0  0      0 188900  35020 842500    0    0     0     4  105  200  2  1 97  0  0
 2  0      0 188800  35020 842600    0    0     0     0  160  310 15  5 80  0  0
```

---

# 三、各字段详解

## 1）procs（进程）

| 字段 | 含义                      |
| -- | ----------------------- |
| r  | 等待 CPU 运行的进程数（Runnable） |
| b  | 不可中断睡眠的进程（通常等待磁盘 IO）    |

例如：

```
r=8
```

表示有8个进程等待CPU。

如果：

```
r > CPU核心数
```

通常说明

> CPU资源不足。

例如：

4核CPU

```
r = 12
```

CPU压力比较大。

---

## 2）memory（内存）

| 字段    | 说明            |
| ----- | ------------- |
| swpd  | 已经使用的Swap(KB) |
| free  | 空闲内存          |
| buff  | Buffer缓存      |
| cache | Page Cache缓存  |

例如：

```
swpd = 0
```

说明没有使用交换区。

如果：

```
swpd 持续增加
```

通常说明：

内存不足。

注意：

Linux 会尽量使用空闲内存做缓存，因此：

```
free 很小
```

**不一定表示内存不足**。

真正要结合

```
cache
```

一起看。

---

## 3）swap（交换）

| 字段 | 说明                   |
| -- | -------------------- |
| si | 每秒Swap In（从Swap读回内存） |
| so | 每秒Swap Out（写入Swap）   |

正常情况下：

```
si = 0
so = 0
```

如果：

```
si、so 持续大于0
```

说明：

系统正在频繁交换。

例如：

```
si = 120
so = 350
```

表示：

每秒有大量页面在Swap与内存之间交换。

这通常意味着：

> 内存严重不足。

---

## 4）io（磁盘IO）

| 字段 | 说明                |
| -- | ----------------- |
| bi | Block In，每秒读磁盘块数  |
| bo | Block Out，每秒写磁盘块数 |

例如：

```
bi = 2000
bo = 50
```

表示：

系统主要在读磁盘。

如果：

```
bo 很高
```

可能：

* 写日志
* 数据库存储
* 大文件复制

---

## 5）system（系统）

| 字段 | 说明        |
| -- | --------- |
| in | 每秒中断次数    |
| cs | 每秒上下文切换次数 |

例如：

```
in = 1200
cs = 3500
```

说明：

系统发生了大量中断和线程切换。

如果：

```
cs 非常高
```

可能：

* 线程过多
* 锁竞争严重
* 调度频繁

---

## 6）cpu（CPU）

| 字段 | 说明                 |
| -- | ------------------ |
| us | 用户态CPU时间           |
| sy | 内核态CPU时间           |
| id | 空闲CPU              |
| wa | 等待IO时间             |
| st | 被虚拟机偷走CPU时间（Steal） |

例如：

```
us sy id wa st
20  5 70  5  0
```

表示：

* 用户程序占20%
* 内核占5%
* 空闲70%
* 等待IO 5%

---

# 四、CPU指标如何判断

例如：

```
us = 80
```

说明：

CPU主要运行应用程序。

例如：

```
sy = 40
```

说明：

CPU大量时间用于系统调用。

例如：

```
wa = 35
```

说明：

CPU一直等待磁盘。

即：

> CPU并不忙，而是磁盘太慢。

---

# 五、st（Steal）是什么？

如果是在：

* VMware
* KVM
* Xen
* 云服务器

会看到：

```
st
```

例如：

```
st = 20
```

表示：

CPU有20%的时间被宿主机分配给其他虚拟机。

即：

不是你的程序慢，

而是：

> 宿主机CPU资源紧张。

# 六、常用参数

### 查看磁盘统计

```bash
vmstat -d
```

输出：

```
disk-reads writes
```

统计每块磁盘的读写情况。

---

### 查看磁盘分区

```bash
vmstat -D
```

显示：

* 磁盘数量
* 分区数量
* 总读写次数

---

### 查看SLAB

```bash
vmstat -m
```

查看：

Linux内核SLAB缓存。

适合排查：

* 内核内存泄漏
* SLAB占用过高

---

### 查看事件统计

```bash
vmstat -s
```

输出类似：

```
1024000 K total memory
256000 K used memory
768000 K free memory
...
```

适合查看累计统计信息。

---

# 七、实际排查案例

### 案例1：CPU高

```text
r  us sy id wa
10 80 15  5  0
```

分析：

* `r` 很大，说明大量进程等待 CPU。
* `us+sy` 接近 100%，CPU 已接近满载。

建议进一步使用 `top`、`htop` 或 `pidstat` 查看占用 CPU 的进程。

---

### 案例2：内存不足

```text
swpd  si  so
500000 300 200
```

分析：

* 已使用大量 Swap。
* `si`、`so` 持续大于 0，说明系统正在频繁换页（Swap Thrashing）。

建议检查内存占用，使用 `free -h`、`top`、`smem` 等工具分析，必要时增加内存或优化应用。

---

### 案例3：磁盘瓶颈

```text
wa = 45
```

分析：

CPU 有近一半时间在等待 I/O，而不是执行计算。

建议结合 `iostat -x`、`iotop`、`sar -d` 等工具分析磁盘利用率、队列长度和具体 I/O 来源。

---

# 八、与其他性能命令的配合

| 命令             | 主要用途                      |
| -------------- | ------------------------- |
| `vmstat`       | 系统整体运行状态概览（CPU、内存、I/O、进程） |
| `top` / `htop` | 查看进程级 CPU、内存使用情况          |
| `free -h`      | 查看内存和 Swap 使用情况           |
| `iostat -x`    | 分析磁盘 I/O 性能和设备利用率         |
| `pidstat`      | 按进程统计 CPU、内存、I/O 使用情况     |
| `sar`          | 收集和查看历史性能数据               |
| `mpstat`       | 查看各 CPU 核心负载情况            |

## 九、总结

`vmstat` 是 Linux 性能分析中最基础、最实用的工具之一。一般可以按照以下顺序快速判断系统状态：

1. **看 `r`**：判断 CPU 是否存在排队。
2. **看 `us`、`sy`、`id`、`wa`**：判断 CPU 是计算繁忙还是等待 I/O。
3. **看 `swpd`、`si`、`so`**：判断是否发生内存交换。
4. **看 `bi`、`bo`**：了解磁盘读写压力。
5. **看 `in`、`cs`**：判断中断和上下文切换是否异常。

通过这几个关键指标，通常可以在几秒钟内判断问题大致属于 **CPU、内存、磁盘 I/O** 还是 **系统调度**，再结合 `top`、`iostat`、`pidstat` 等工具进行深入定位。
